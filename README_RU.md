# LocalDocRenamer

Локальный анализ документов и безопасное переименование. Русский настольный интерфейс,
Qwen3 4B Q4_K_M GGUF через llama.cpp, Tesseract rus+eng. Модель и среда выполнения
входят в установочные комплекты. Python, Office, OCR и llama.cpp отдельно не нужны.

Ссылки на сборки и их фактический статус приведены в [README.md](README.md).
Результаты проверки и её границы: [VERIFICATION_RU.md](VERIFICATION_RU.md).
Установка и первый документ: [INSTALL_RU.md](INSTALL_RU.md).

## Возможности

Файлы, папки с подпапками, перетаскивание, пакетная очередь, предпросмотр имени,
редактирование полей и имени, подтверждение каждой строки, пакетное переименование,
отмена после перезапуска, экспорт JSON/XLSX, локальный журнал с очисткой.
Модель работает в отдельном потоке; остановка выполняется между фрагментами.

Извлекаются тип, организация, номер, дата, тема, ИНН, сумма, валюта и контрагент.
Строгая JSON-грамматика применяется при генерации; результат повторно проверяется
по схеме. Значения сопоставляются с цитатами из исходного текста. ISO-дата,
десятичная сумма и код валюты могут подтверждаться равнозначной дословной записью
в документе. Для ИНН проверяются контрольные цифры. Неподтвержденные и противоречивые
значения возвращаются как null и требуют проверки. Сумма хранится строкой для
сохранения десятичной точности. Валюта: RUB/USD/EUR/CNY/GBP либо null.

Цитата не доказывает правильность выбора реквизита или роли стороны. Перед
переименованием пользователь должен проверить результат. Отсутствие даты, типа,
номера или организации блокирует имя; поля можно исправить по оригиналу.
Ошибка чтения, OCR или JSON блокирует переименование до повторного успешного анализа.

Шаблон: `Дата_ТипДокумента_Номер_Организация.расширение`. Исходное расширение
сохраняется. Запрещенные символы и зарезервированные имена Windows очищаются;
коллизии и перезапись блокируются. Перед операцией сверяется SHA-256 документа.
Журнал SQLite сохраняет подготовленные и завершенные операции. Отмена проверяет
содержимое и свободное исходное имя. Пачка состоит из отдельных операций;
уже выполненные операции остаются доступными для отмены при ошибке следующего файла.

## Форматы

| Формат | Обработка |
|---|---|
| PDF | Текст PyMuPDF и локальный OCR сканированных страниц |
| JPG/JPEG/PNG | Tesseract rus+eng, учет ориентации EXIF |
| DOCX | Текст XML, колонтитулы, сноски; OCR крупных PNG/JPEG внутри документа |
| DOC | Комплектный antiword, текстовый слой |
| XLSX | openpyxl, все листы, значения без исполнения формул |
| XLS | xlrd, сохраненные значения всех листов |
| TXT/CSV | UTF-8, UTF-16 с BOM, Windows-1251; CSV как текст |

Лимиты: 150 МБ на файл, 200 страниц PDF, 300 000 символов, 50 000 строк таблицы,
2000 файлов в очереди. Превышение блокирует анализ; частичный результат не используется.
Пустые, поврежденные, защищенные и нечитаемые файлы не переименовываются.

XLSX с формулами или встроенными изображениями блокируется: нужна копия со значениями
или отдельное извлечение изображений. В XLS читаются сохраненные значения, которые
могут устареть. Изображения внутри старых DOC/XLS и все виды сложных объектов Office
не поддерживаются полноценно. Проверка простых файлов не означает поддержку любых
вариантов этих форматов.

Переименование требует жестких ссылок: NTFS, APFS или HFS+. На exFAT операция
завершится ошибкой с сохранением исходника. Не редактируйте документ другой
программой одновременно с анализом и переименованием. История отмены не заменяет
резервную копию; устойчивость к аварийному отключению питания отдельно не испытана.

## Офлайн-работа

Qwen запускается внутри процесса через llama-cpp-python, без HTTP-сервера и внешних
AI API. Приложение не скачивает модели и не содержит аналитики или телеметрии.
Другой локальный Qwen3 4B/8B GGUF можно выбрать в настройках; стандартный комплект
содержит только 4B. Совместимость каждого стороннего GGUF нужно проверять отдельно.

Python-сокеты запрещены. На Windows установщик создает правила блокировки исходящих
соединений для всех комплектных EXE; приложение проверяет активность правил и Windows
Firewall перед обработкой и отказывает при отсутствии защиты. На macOS применяется
системная песочница с запретом сети, наследуемая дочерними процессами.
Сетевые диски, пути и символьные ссылки отвергаются. OCR передает изображения локально
через stdin/stdout. Загрузчик публичных зависимостей работает только при сборке
и не включается в приложение.

Настройки и журнал: `%LOCALAPPDATA%/LocalDocRenamer` на Windows,
`~/Library/Application Support/LocalDocRenamer` на Mac. При наличии `portable.flag`
на Windows используется `state` рядом с программой. Для переносной папки правила
firewall необходимо создать заново для её полного пути. Основная поставка Windows
является установщиком.

Распознанный текст хранится в памяти до очистки или выхода. Журнал отмены содержит
пути и хеши; экспорт сохраняет реквизиты и цитаты по выбору пользователя. Программа
не управляет системным swap или crash dump. Экспорт использует локальный временный
файл рядом с результатом; после аварийного завершения ОС он может остаться.
Не используйте папки, синхронизируемые сторонними облачными программами, для
конфиденциальных документов. Защита приложения не управляет такими программами.

## Сборка разработчиком

Нативные комплекты собираются отдельно на Windows и Intel macOS через GitHub Actions.
Windows: `.github/workflows/build.yml`; исходный проверочный вариант этого workflow
может также находиться в `build-installers.yml` в ветках сборки.
Старый Mac: `.github/workflows/build-macos2011.yml`.

Windows использует Python 3.11, PySide6, CPU llama.cpp и Inno Setup 6. Mac использует
Python 3.10, PyQt5/Qt 5.15.2, CPU llama.cpp без Metal и AVX2, старые нативные OCR/JPEG
с целевым macOS 10.13. Патч filesystem устраняет зависимость llama.cpp от API macOS 10.15.
Полный комплект проверяется на минимальные версии всех Mach-O библиотек.

Mac требует Intel x86_64 с AVX и как минимум High Sierra 10.13. Для 4B желательно
8 ГБ памяти. Производительность и запуск на физическом Mac 2011 пока не измерены.
Используется ad-hoc подпись; Developer ID и notarization Apple отсутствуют.

Публичные модели, языки и библиотеки загружаются только на сборочной машине.
Происхождение и SHA-256 фиксируются в `asset-provenance.json`; лицензии и исходники
нативных компонентов входят в комплект. Не все зависимости зафиксированы по хешам;
повторная сборка может отличаться. Пользовательские документы в CI не используются.

`--self-test <report.json>` проверяет ОС-защиту от сети, OCR, чтение PDF/DOCX/XLSX,
изображения и сканированного PDF, реальную генерацию Qwen, схему, номер и дату,
переименование и отмену с сохранением байтов. В CI установщик Windows также
выполняется, после чего проверяется установленная копия с очищенными переменными
Python и PATH. Mac DMG монтируется, подпись приложения внутри проверяется повторно.
