# LocalDocRenamer

**Статус поставки: исходный проект для Windows x64 и macOS Intel, НЕ готовая установленная программа.**
В этом архиве нет EXE, модели GGUF, Windows OCR, antiword и их DLL.
Завершение ТЗ требует сборки полного комплекта и приемки на Windows 10/11 x64 и macOS Intel.
Не используйте исходный проект как подтверждение выполнения критериев приемки.

## Что реализовано

Настольный интерфейс на русском: файлы, папки с подпапками, drag-and-drop, очередь,
предпросмотр имени, реквизиты, цитаты и распознанный текст. Работа модели в отдельном
потоке. Ручная корректировка полей и имени. Пакетное переименование подтвержденных
строк, экспорт JSON/XLSX и локальный журнал. Остановка между фрагментами документа.

Модель Qwen3 4B/8B GGUF запускается через llama-cpp-python, нативную обертку llama.cpp,
внутри процесса, без HTTP, облачного API и отдельного сервера. CPU-вариант сборки.
Выбор файла модели доступен в интерфейсе. Автоматического скачивания в приложении нет:
готовую поставку собирают сразу с моделью. Проверяется архитектура qwen3 и имя 4B/8B
в метаданных; совместимость конкретного GGUF подтверждается приемкой.

Модель ограничена JSON-грамматикой. После генерации JSON заново проверяется по схеме.
Для значений запрашиваются дословные цитаты, проверяется их присутствие в тексте,
для ИНН проверяются контрольные цифры. Не подтверждено: null. Противоречия между
фрагментами: null. Даты проверяются по календарю, суммы сохраняются строками во
избежание ошибок float. Валюта: RUB/USD/EUR/CNY/GBP либо null.

Важное ограничение: цитата не доказывает правильность роли стороны и выбора реквизита.
Модель может выбрать номер из приложения, покупателя вместо продавца или неверную
дату. Поэтому любое переименование требует ручной проверки. Абсолютное отсутствие
семантических ошибок нейросети не гарантируется.

Если нет даты, типа, номера либо организации, имя не формируется и переименование
блокируется. Отсутствующие обязательные поля можно вручную заполнить по оригиналу.
Необязательные поля могут остаться null. Ошибка чтения/OCR/JSON блокирует операцию,
ее нельзя снять одной отметкой подтверждения. Нужно устранить причину и повторить анализ.

## Форматы и ограничения

| Формат | Обработка |
|---|---|
| PDF | PyMuPDF: текст + OCR страниц с крупными изображениями или малым количеством текста |
| JPG/JPEG/PNG | Tesseract, rus+eng, ориентация EXIF, локальная передача через stdin/stdout |
| DOCX | Прямое чтение XML текста, колонтитулов, сносок; OCR крупных встроенных PNG/JPEG |
| DOC | Bundled antiword, текстовый слой; встроенные изображения не распознаются |
| XLSX | openpyxl, все листы, без исполнения формул и внешних ссылок |
| XLS | xlrd, все листы, сохраненные значения; внешние ссылки не обновляются |
| TXT/CSV | UTF-8, UTF-16 с BOM, Windows-1251; CSV читается как текст |

PDF до 200 страниц, файл до 150 МБ, текст до 300 000 символов, таблицы до 50 000 строк,
очередь до 2000 файлов. При превышении анализ блокируется: частичного результата нет.
Лимиты заложены для предсказуемого расхода памяти; время на большие документы
не измерено. Анализ идет по перекрывающимся фрагментам, противоречия требуют проверки.

XLSX с формулами или вложенными изображениями блокируется. Для него нужна копия со
значениями или отдельное извлечение изображений. XLS возвращает сохраненные значения,
они могут устареть. Изображения внутри старых DOC/XLS полноценно не поддержаны.
Сложные текстовые поля, SmartArt и отдельные виды объектов Office не гарантируются.
Пустые, защищенные, поврежденные и нечитаемые файлы не переименовываются.
Это ограничения относительно полного ТЗ, а не заявленная полная поддержка всех случаев.

## Сборка полного Windows-комплекта

Это действия разработчика на сборочном ПК. Конечный пользователь ничего из этого
не устанавливает.

1. Windows x64, Python 3.11 x64, Visual Studio Build Tools с Desktop C++ и CMake, Inno Setup 6.
2. Получить проверенную Windows-сборку Tesseract и ВСЕ ее DLL, языки rus/eng.
   Скопировать целиком в `vendor/tesseract`, основной файл `tesseract.exe`.
3. Подготовить Windows antiword с его DLL и UTF-8 mapping:
   `vendor/antiword/antiword.exe`, `vendor/antiword/UTF-8.txt`.
   Само наличие файла недостаточно: проверить на реальном DOC.
4. Скачать Qwen3 4B или 8B GGUF с официального репозитория Qwen. Поместить в `models`.
   Приложение не скачивает ничего при запуске и не умеет восстанавливать отсутствующую модель.
5. В `vendor/licenses` положить тексты лицензий, атрибуцию и необходимые исходники
   сторонних компонентов. Создать `CONTENTS.txt` со списком версий и происхождением.
   См. `THIRD_PARTY_NOTICES.md`.
6. Выполнить из PowerShell:
   `powershell -ExecutionPolicy Bypass -File scripts/build-windows.ps1`
7. Папка `dist/LocalDocRenamer` содержит EXE, Python runtime, библиотеки, vendor и модели.
   Передавать нужно ВСЮ папку. Один EXE без соседних файлов работать не будет.
8. Сценарий также собирает установщик через Inno Setup 6: `release/LocalDocRenamer-Setup-Windows-x64.exe`. Если компилятор не найден, сборка установщика останавливается.
9. Пройти `ACCEPTANCE_RU.md` на чистых Windows 10 и 11 x64 без Python.

Сборка намеренно останавливается, если нет модели, OCR, antiword или лицензионных
материалов. Пустые папки не подменяют комплект поставки. Версии Python-зависимостей
ограничены диапазонами, полноценного воспроизводимого lock-файла пока нет. После
проверки Windows-сборки нужно зафиксировать версии, включая bundled llama.cpp,
и сохранить `pip freeze` вместе с хешами внешних пакетов.

## Работа пользователя с готовой сборкой

Распаковать полную папку на локальный диск NTFS с правом записи. Запустить
`LocalDocRenamer.exe`. Выбрать включенную модель и документы. Нажать Анализировать.
Открыть строку, сравнить данные и цитаты с оригиналом, исправить при необходимости,
сформировать имя и отметить подтверждение. Нажать Переименовать проверенные.

Копии документов для обработки не создаются. Отмена возвращает исходные имена,
если содержимое не изменилось и исходные имена свободны. Отмена работает после
перезапуска через SQLite-журнал. Не удалять папку `state`, пока нужна история отмены.
Операции записываются по одному файлу. Вся пачка не является одной атомарной транзакцией.
При конфликте уже выполненные операции остаются в журнале и доступны для отмены.

Переименование использует создание жесткой ссылки с запретом перезаписи и удаление
прежней записи каталога; байты документа не удаляются. NTFS поддерживает этот механизм.
На файловой системе без жестких ссылок операция завершится ошибкой, исходник сохранится.
Контроль SHA-256 защищает от использования результата анализа для измененного файла.
Одновременное редактирование документов другими программами во время операций запрещено:
контроль хеша не заменяет эксклюзивную блокировку файловой системы.

Журнал подготовленной операции позволяет восстановиться при завершении процесса между
созданием нового имени и удалением старого. Устойчивость к отключению питания требует
отдельного испытания: SQLite FULL не гарантирует сохранение операций каталога диска
при любой аппаратной неисправности. Резервная копия документов остается необходимой.

## Конфиденциальность

В приложении нет HTTP-клиента, облачного API, аналитики или функции отправки файлов.
Python-сокеты программно запрещены. Сетевые пути, подключенные сетевые диски,
символические ссылки и точки повторной обработки Windows отвергаются. OCR вызывается
локально с аргументами без shell, изображения передаются в памяти. Временный файл
экспорта создается только рядом с выбранным экспортом и удаляется после ошибки;
после аварийного завершения ОС такой файл может остаться, его нужно удалить вручную.

При наличии `portable.flag` локальные настройки/журнал находятся в `state` рядом с EXE.
Иначе в `%LOCALAPPDATA%/LocalDocRenamer`. Извлеченный текст хранится в оперативной памяти
до очистки списка/выхода; Python и ОС не гарантируют криптографическое стирание памяти.
Программа не управляет файлом подкачки Windows и системными crash dump.
Журнал обработки содержит время и коды событий. Журнал отмены содержит исходные и новые
пути, SHA-256 и состояния. Экспорт намеренно сохраняет реквизиты и цитаты по выбору
пользователя. Не размещать документы, экспорт и саму программу в облачно
синхронизируемых папках: чужие программы и Windows могут синхронизировать их независимо.

Программный запрет сокетов не является песочницей для нативных DLL и дочерних EXE.
Для принудительного запрета исходящих соединений на уровне Windows поставлен
`block-network.ps1`: запустить с правами администратора в готовой папке приложения.
Он блокирует все EXE в ней; после перемещения папки правила нужно применить заново.
Обычный запуск приложения прав администратора не требует. Ни эти правила, ни код
не заменяют проверку сетевого трафика фактической сборки. Полная офлайн-проверка
и отсутствие сетевых обращений в этой среде не подтверждены.

Журнал обработки можно очистить. Активная история переименований сохраняется для
отмены. Очистить историю можно после отмены всех операций. Необратимое удаление
истории активных операций через интерфейс намеренно не предусмотрено.

## Дополнение: macOS Intel и автоматическая сборка

Запрошены Windows 10/11 x64 и macOS Intel x86_64. Исходный код использует подходящие
платформе названия нативных утилит; ресурсы PyInstaller читаются из _MEIPASS.
Данные Mac пишутся в ~/Library/Application Support/LocalDocRenamer, вне APP.
Локальность тома Mac проверяется через Darwin statfs64 (MNT_LOCAL). ABI сверялся
с исходным кодом Apple, реальный вызов на Mac еще требует приемки.

LocalDocRenamer.spec описывает упаковку для обеих платформ.
scripts/build-macos-intel.sh создает APP и DMG с ярлыком Applications, моделью и OCR.
Используется ad-hoc подпись: Developer ID и notarization Apple НЕ выполнены,
беспрепятственное открытие через Gatekeeper не обещается.
В Info.plist 13.0 указана как целевая минимальная macOS. Реальная совместимость всех
Qt/Homebrew-библиотек с macOS 13/14 еще не проверена. CI работает на macOS 15 Intel.
Нужно знать версию системы пользователя, прежде чем считать сборку подходящей.

.github/workflows/build-installers.yml предназначен для отдельного репозитория
с этим проектом в корне. Два задания: Windows Server 2022 x64 и macOS 15 Intel.
На этапе сборки разрешен интернет для публичных зависимостей. Пользовательские
документы в workflow не входят. Workflow НЕ запущен; проверен только как YAML.

scripts/prepare-assets.py вызывается ТОЛЬКО на сборочной машине: получает Tesseract,
antiword, языки rus/eng, официальную Qwen3 4B Q4_K_M GGUF и материалы лицензий.
Версия GGUF привязана к commit SHA; хеши записываются в asset-provenance.json.
Часть URL указывает на upstream main: воспроизводимый lock требует фиксации.
Скрипт скачивания не включается в приложение.

--self-test <report.json> у упакованной программы проверяет комплектный OCR,
реальную генерацию JSON Qwen3 на синтетическом договоре, переименование и отмену.
Успех обязателен для workflow, но пока НЕ ПОЛУЧЕН. Workflow сохраняет установщики
как кандидаты и отчеты на 7 дней, без публикации GitHub Release. Приемка на чистых
системах и сетевой аудит остаются обязательными.

Сборки GitHub не запускались: доступные репозитории публичны, нужно согласие
пользователя на размещение исходного кода или выбор приватного репозитория.
